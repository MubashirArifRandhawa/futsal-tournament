# Futsal Cup — live 5-a-side tournament website

A public site (fixtures, results, live scores, table, team sheets, stats) plus an
admin panel. Data lives in **Firebase Firestore**, so every open page updates the
moment the admin changes something, without a refresh. Schedules are generated by
**Gemini (free tier)** through a Netlify Function, with a built-in round-robin
scheduler as a safety net. Nothing is stored in localStorage.

```
public/                 ← the website (deployed by Netlify)
  index.html            public site
  admin.html            admin panel
  css/style.css, css/admin.css
  js/firebase-config.js ← paste your Firebase config here
  js/app.js             public pages
  js/admin.js           admin panel (DEFAULT_TEAMS at the top)
  js/data.js            realtime Firestore store + standings/stats
  js/ui.js              crests, shirts, pitch/team sheet, tables
  js/scheduler.js       round-robin + checks (shared with the function)
netlify/functions/generate-schedule.mjs   ← calls Gemini, key stays secret
firestore.rules         ← security rules: public read, admin write
netlify.toml
```

## 1. Firebase (free Spark plan)

1. Go to <https://console.firebase.google.com> → **Add project**.
2. **Build → Firestore Database → Create database** (production mode, any region).
3. Firestore → **Rules** tab → paste the contents of `firestore.rules` → **Publish**.
4. **Build → Authentication → Get started → Email/Password → Enable**.
   Then **Users → Add user** with your admin email and password.
5. **Project settings (gear) → General → Your apps → Web (`</>`)** → register an app
   and copy the `firebaseConfig` values into `public/js/firebase-config.js`.
6. Authentication → **Settings → Authorized domains**: add your Netlify domain
   (e.g. `your-site.netlify.app`) once you know it.

**Make yourself admin:** open `/admin.html` on your site and sign in. The page shows
your UID. In Firestore create a collection `admins` and add a document whose
**Document ID is that UID** (no fields needed). Reload: you're in. Repeat for any
other admins.

## 2. Gemini API key (free)

1. Go to <https://aistudio.google.com/apikey> → **Create API key**.
2. Keep that Google Cloud project **without billing** so it stays on the free tier.

Note: on the free tier Google may use prompts to improve its products. The only
data sent is team names and timing settings.

## 3. Deploy on Netlify

Functions need a Git or CLI deploy (drag-and-drop "Netlify Drop" only serves static
files, so the Gemini button would fall back to the built-in scheduler).

**Option A, GitHub:** push this folder to a repo → Netlify → **Add new site → Import
an existing project** → pick the repo. Build command: *(empty)*. Publish directory
and functions folder come from `netlify.toml`.

**Option B, CLI:** `npm i -g netlify-cli` → `netlify login` → `netlify deploy --prod`
from this folder.

Then **Site configuration → Environment variables** and add:

| Key | Value |
|---|---|
| `GEMINI_API_KEY` | your key from AI Studio |
| `FIREBASE_PROJECT_ID` | your Firebase project ID (only signed-in admins can then use the AI quota) |
| `GEMINI_MODEL` *(optional)* | comma-separated models to try in order. Default `gemini-2.5-flash,gemini-2.5-flash-lite,gemini-3.1-flash-lite` |

Redeploy after adding variables.

Local preview with functions: `netlify dev` (opens on http://localhost:8888).

## Using it

**New tournament** (`/admin.html` → *+ New tournament*):
1. Name, venue, start date/time, **total time available**, format
   (round-robin, round-robin + final, or double round-robin). Timing options let you
   fix the match length, half-time, breaks and number of courts. Leave the match
   length blank and Gemini picks the longest length that fits.
2. Teams: name, 3-letter short name, shirt and trim colours. Five are pre-filled;
   edit `DEFAULT_TEAMS` at the top of `public/js/admin.js` to change the defaults.
3. **Generate with Gemini** → review the schedule → **Create tournament**.

The server re-checks Gemini's answer (every pair plays the right number of times,
nobody plays twice at once) and recalculates all kick-off times itself. If Gemini
is unavailable or wrong, the built-in scheduler is used, and the page tells you.

**Squads:** *Teams & squads* → *Edit squad*: 5 starters + 5 substitutes with shirt
number, name, position (GK/DEF/MID/FWD) and captain. The formation (e.g. 2-1-1) comes
from the positions, and the pitch preview updates as you type. Tap ⇅ on two rows to
swap a starter and a sub, or paste a list (`10 Ali Khan FWD`, one per line).

**Running the day:**
- **Start tournament** marks it live on the public site.
- On the matches list, **Edit** sets the **referee**, kick-off, teams, and length.
- **Run match** → **Kick off** (saves both line-ups) → add goals, own goals, cards and
  subs → **Half-time** → **Start 2nd half** → **Full time**. Pause/resume and ±10 s /
  ±1 min adjust the clock. Scores are calculated from goal events, so deleting a wrong
  goal fixes the score.
- For a **Final**, open *Edit* and press *Fill with 1st & 2nd from the table*;
  enter penalties there if needed.
- **Feature on site** chooses which tournament the public site opens. Visitors can
  switch to older tournaments from the header.

## Data model (Firestore)

```
config/site                     { activeTournamentId }
admins/{uid}                    {}                     (created by hand)
tournaments/{tid}               name, venue, status, startAt, totalMinutes,
                                matchMinutes, halftimeMinutes, breakMinutes,
                                courts, format, schedule{source,model,summary}
tournaments/{tid}/teams/{id}    name, short, color, color2, gkColor, coach,
                                logoUrl, order, players[{id,number,name,
                                position,role,captain}]
tournaments/{tid}/matches/{id}  round, slot, court, stage, homeId, awayId,
                                kickoffAt, matchMinutes, status, period,
                                clock{running,startedAt,elapsedMs}, events[],
                                homeScore, awayScore, referee, lineups, shootout
```

The live clock uses each device's own time. Phones and laptops set their clocks
automatically, so this is accurate to about a second.

## Free-tier capacity

Firestore Spark allows 50,000 document reads a day. Each visitor reads the
tournament once, then about one read per change while they watch. That covers a
local tournament with a few hundred spectators comfortably.
